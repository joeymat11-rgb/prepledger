3.1  COMMIT MESSAGE (verbatim)

PROGRESSION-1 FIX-4 v7.56.0 — the derivation is bounded by the load tenure, the mint reads its trace, and a receipt is deduped by fact, never by its sentence

Sol's PACK-2 verdict, all three blockers plus both hunts. Built on c0bb384.

§1 [P0] A6-1 — A LOAD IDENTITY CHANGE ENDS THE RUN. The derivation walked every
session at the current load and its fall-off rule fired only when the FAILED
line's load equalled topAt, so an excursion was invisible: a top at 250, a
non-top at 245, a top back at 250 read as TWO sightings where the walk reads
one. A plain boot then disagreed with the walk on a single device. Worse,
_mintJointEarn rescanned ALL historical tops at the current load, pairing any two
PROVISIONAL days whatever lay between them — so merge(m,m) on that one-device
history MINTED an earn and bought 255. The derivation now walks only the maximal
contiguous tenure at the current load, and the mint consumes THAT walk's own
trace — the run it counted and the pair it counted it from. One tenure
computation, in one helper, read by the prefix rule and the derivation both,
because the whole defect was two readers of one history disagreeing. The trace is
also the mint's ONLY gate now: a run check beside it was a second source of truth.

§2 [P0] A6-2 — DEDUPE BY FACT, NOT BY THE SENTENCE. "PRESS 255 EARNED" is a
display title, and a lift that graduates to 255, runs it, deloads and earns 255
again prints the identical words — so the mint's title test suppressed a
LEGITIMATE re-earn and left the record unspent, one honest session from buying
the load twice. And every debut writer now carries the graduation's day in its id
(q_<ex>_<newW>_<dEarn>, all four writers plus the mint through earnWalk): the id
q_press_255 was reused by every graduation to 255 the lift ever made, so a
COMPLETED debut and an ACTIVE one shared a key and were one MERGE_KEYED pass from
collapsing into each other. Existing queue items are never rewritten and every
already-check is id-independent. Measured: the merge now queues the SAME id the
serial walk queues for the same graduation.

§3 [P1] A5 — A SAME-DAY APPLY AND UNDO CANNOT RECLASSIFY A PARTIAL AS COMPLETE.
Receipts carry a date, not an instant, so a +1 and a -1 filed on one day are
indistinguishable in order; the naive walk-back saw the net zero, judged a
three-of-four line against three, and a session the WALK refused to count banked
a sighting at the next boot and earned the load a session early. Completeness on
a day is judged against the maximum count plausibly active during it: what the
later receipts imply, plus every +1 filed on the day itself. The derivation also
stopped judging each entry against its own delivered length — which makes any
line trivially complete — and judges it against the count the lift carried that
day. T20 is unaffected (its push receipts are on later days). New VOLUME receipts
carry an "at" instant: additive, unread this round, so a future rebuild can order
same-day events exactly instead of inferring a maximum.

§4 [P1] Hunt 2 — THE PROPOSED DEBUT WRITERS CARRY THE VECTOR TOO. FIX-2 taught
the classic earn to mint newWSets and stopped there, so the two-rung and
one-sighting offers queued with none and rendered a scalar debit for a lift that
runs three different weights. Both writers mint it, shifted by their own jump.
And TAKING an offer is engine law now, not a gesture inside the tap handler:
takeProposedDebut supersedes every LOWER graduation still standing for that lift,
