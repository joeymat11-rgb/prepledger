# Independent import-guard expectations

This is an expectation authoring carrier, not a candidate engine, repair control, or accepted PACKAGE verdict. The real extracted candidate and actual source mutants run separately. Synthetic data only.

`build-import-guard-expectations.cjs` compiles the manifest-pinned public `fe516c1` source using the existing public-reference builder. The frozen helper prioritizes actual bundle exports, including `migrate`, `isPristineSeed`, `dataLossGuard` and their actual `SEED`; pinned source supplements provide only missing exports. It never loads the extracted engine factory. The source receipt is frozen and branded in a private WeakSet: candidate directories, candidate files, forged receipts and alternate bundle parameters are refused before import.

For each of the 208 cases and four accepted Date/clock cells, the builder first executes an unprojected literal-frozen carrier and requires its complete typed trace to equal the actual target worker byte-for-byte. It then applies only the closed per-case/per-call projection table in `import-guards-expectations.cjs`:

- D33: exact literal guard results from the accepted identified-day/entry/slot/skipped/multiset rules, including existing earlier loss reasons. Positive controls use the actual frozen guard.
- D34: fixed false predicate results for the authored equal-fingerprint content edits. `IG34-MARKER-EXISTING` explicitly has two false predicate calls even though its existing marker preserves the final GREEN assertions: boot skips its redundant marker write and the unchanged offer OR reads the existing marker. Real seed, ordering and excluded-family positives use the actual frozen predicate.
- D35: only the separately named ordinary-data future61/string61 cases return their original input without calling migration. Supported migrations remain literal frozen executions.

Every projected call has an exact occurrence count and source/claim citation. An unknown, extra, or missing projected call fails. The profile and nested literals are frozen. The unchanged frozen host snippets consume those results, so marker, save-banner, durable-copy and remote-only sync consequences follow their actual control flow. No new host rule is modeled.

The expected graph therefore exists independently of the candidate. Exact baseline-to-expected cells bind the complete original trace hash; the later real candidate must match every remaining typed byte, descriptor, alias and receipt. Fixture generation never reads candidate outcomes or updates itself after a mismatch.

The remote-rich ghSync case has one explicit source-derived frame correspondence. Frozen12364–12368 calls `todayStart` and `isoOf` only after its guard permits the write. Two refused attempts therefore remove original frames9,8,4,3 (descending); original frames0,1,2,5,6,7,10 remain, at final indexes0–6. Both original and final name inventories are asserted. `afterPath` identifies the final frame index for an otherwise identical retained leaf path. No complete retained observation is replaced or ignored.

That host uses an explicit injective identity mapping obtained from corresponding retained frozen/expected graph objects. Deleted-only identities receive collision-free spare IDs, preserving the existing bijection check. Every reference occurrence and the reconstructed whole trace are checked; this is renaming of trace identifiers, not removal of identity evidence. Other cases use exact numeric identity cells. Ordinary numeric data is never exempted.

Reproduce from the repository root, using a real `node_modules` directory and the pinned esbuild dependency:

```
node --test rebuild/conform/v4/postfix/test/expectation-carrier.test.cjs
node rebuild/conform/v4/postfix/helpers/build-import-guard-expectations.cjs
```

The builder writes only ignored `.tmp/postfix/expectation-build/import-guards-deltas.json`. The reviewed tracked fixture is a separate publication step. Selecting case IDs after the command is useful for diagnosis and overwrites only that scratch output; it is not full832 construction. The accepted PACKAGE independently executes literal frozen and real candidate cases, checks the fixture, applies actual source mutations, and runs all legacy gates. A fixture or this carrier cannot mark the package accepted.
