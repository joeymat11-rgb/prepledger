## Observed delays
- Completed workers were sent send_message and stayed idle. The matrix author and reviewer were both completed when PM checked; a correction was outstanding.
- Broad graph classifications overstated protected boundaries: the public engine-runtime factory composition was incorrectly treated as importing protected index.
- Evidence publication was fragmented. Eighteen PM documentation/ledger commits span15:32-16:51; some checkpoints immediately lagged the next ledger line.
- Tests already measured in isolated copies were short; source preparation, review handoffs and PM publication dominated their path to adoption.
- Independent review was valuable: it caught false execution boundaries and preserved the expected-red release case instead of relabeling it green.
- These observations justify removing coordination delay, not reducing test coverage or review independence. No numerical speedup is claimed yet.

## Effective now
1. On a completion event, dispatch ready work with followup_task. send_message is for an already-running recipient. Never equate delivered text with an active worker.
2. Keep existing workers. Author and reviewer go directly round-by-round until ACCEPT, disagreement or round3; PM makes the final integration decision.
3. Give each active worker one bounded deliverable on the current critical path. Preserve the owner queue; no filler work or speculative new lanes.
4. Require an actual evaluated call/read path for every execution STOP. A directory name, comment, import regex or aggregate map alone cannot establish that boundary.
5. Reuse reviewed graphs and source proofs by exact source/argv/blob identity. Review changed code or new edges; do not re-audit accepted unchanged modules after metadata-only edits.
6. Batch compatible metadata fills and evidence publication. One concise wave receipt plus immutable machine evidence and independent verdict is enough; no separate report for each copy/formatting step.
7. A complete independent readiness verdict bound to exact source, command and effects starts the authorized next step immediately. Do not wait for its prose file to be packaged; preserve that file before final acceptance.
8. Keep one runtime slot and its existing owner/queue. Static preparation and independent review run in parallel with the currently approved test; tests sharing the slot stay serialized.
9. Prioritize completed-run result review and ready execution before starting another broad inventory. Unexpected behavior, drift or a new boundary stops the affected command only.
10. Preserve actual red evidence and full test targets. Run targeted checks for changes, then all required exact-head Windows/Linux and final package checks; no repeated broad tests without changed inputs or unresolved concern.
11. Publish accepted work in small durable batches. Update the single current PM checkpoint with that batch; avoid separate status-only commits and duplicate narrative reports.
12. Owner questions cover genuine product/private/spending/release guard decisions only. Prepare a concrete reviewed scope first; reuse existing authorization and do not ask twice for the same action.
