# B1+B2 native capture — planning alternatives after PM362

Status: planning only under PM's362 disposition. Neither option is implemented, tested or accepted. The current prototype remains R1 OPEN/REJECT.
Evidence: preimagebe0aeeb6; Promise red8ab80f3b; intermediate0282f3f2; actual non-Promise refutationd05ef3e9. The helper's no-argument callback cannot stop Node from reading an application resource first.
Common bar: preserve the exact original child command/outcome/objects/reactions/first failure; distinguish actual child result from capture validity; keep fixed two-record diagnostics; detect missing, extra and late observations even if a later diagnostic write fails.
Common constraint: parent waits for actual child termination. A successful file written earlier cannot prove no later observation occurred. Adding a final fallible refusal write, another exit listener, finite drain rounds or a timeout does not close this gap.

## 1. Parent checks an exact runtime call census at terminal shutdown
Candidate mechanism: remove async resource/Promise observers and child-side success publication. After child termination, the operator validates fixed diagnostic records plus a runtime-generated call count for the exact observation function.
Possible existing runtime surface: node:v8 exports takeCoverage/stopCoverage from its native profiler binding (v8:53-56,471-472). Their internals and terminal timing have NOT been inspected or licensed for use.
Original outcome: runtime counters would avoid JavaScript observer callbacks and application resource-property reads. This is a hypothesis; enabling coverage may still affect execution and must earn the same parity tests.
Late/missing evidence: an exact final count other than two refuses; a missing/partial/incorrect-source census refuses. Parent must prove the census was captured after the last possible JavaScript observation, not merely read after termination.
Irreducible gap: a snapshot taken in an exit listener can precede later microtasks, repeating the already-demonstrated false PASS. A complete-looking early coverage file is insufficient. An authoritative native terminal snapshot must actually exist and survive the failure rules.
Additional inputs/capabilities needed: explicit authority for the pinned Node coverage/profiler route and its exact shutdown wiring; proposed source inputs internal/process/coverage and associated startup/termination callers must first be identified/verified in a new commission. Native profiler finalization may require separately licensed native-source inspection.
Additional custody: any raw process-wide coverage output must stay private, since paths/source-map content may exceed this public diagnostic schema. A deterministic local reduction to this exact helper/source/function count would need an approved format and identity contract.
Affected paths if feasible: helper completion block, operator terminal validation, public test, helper.post, report; additional private evidence contract/routine would require its own explicit path grant. Original argv and native assertions remain fixed.
Concrete acceptance test: normal4/4 and all existing failure/census/privacy tests; original Promise and resource parity; third observation in nested/precreated/async-await work; force an early snapshot then a later observation plus unavailable final write, which MUST refuse. Also reject stale, truncated, missing and wrong-source coverage.
Disposition: unproved within the inspected closure. Do not infer terminal timing from the export name or implement an exit-time coverage flush as a fix.

## 2. Parent reads a fixed shared atomic state after child termination
Candidate mechanism: a private parent-owned shared memory slot records observation progress. Each observation marks its attempt before any fallible diagnostic work; only a completed write advances progress, and any extra attempt moves to an irreversible refused state.
Use a small saturating state machine, not a wrapping counter: none → first-pending → first-complete → second-pending → second-complete; every invalid/extra/error route → refused. Parent accepts only second-complete plus valid diagnostics and actual4/4 exit0 after termination.
Original outcome: the child would use a captured atomic primitive on its own fixed shared slot, with no async hooks, scheduler changes, Promise tagging or reads from application resources.
Late/missing evidence: a late third attempt changes the shared slot before a diagnostic write can fail. A child dying mid-write leaves pending/refused. The parent owns a live mapping and reads it after every authorized writer has terminated.
Irreducible assumptions: attaching/initializing the mapping must finish before any success state; subsequent atomic updates must remain valid and nonthrowing; the slot cannot be detached/unmapped or replaced through an application route; memory visibility and all Node test-worker writers must be proved. Parent close alone cannot exclude an independently surviving writer.
Additional capability needed: an OS-backed shared mapping exposed to the existing Node child as a stable atomic view. No suitable cross-process mapping binding has been identified in the inspected Node closure; do not invent one or substitute a worker-thread host for the fixed child command.
Additional inputs needed before work: a separately selected/pinned minimal mapping implementation and full loader/native lifecycle/ACL closure, exact writer ownership/termination model, fixed private slot protocol and failure model. This is a new native dependency/channel, currently unlicensed.
Affected paths if feasible: helper entry/completion state and operator mapping/custody, public test, helper.post, report; any native binding/build/source needs separately enumerated paths. The existing diagnostic schema and native comparison assertions need not change.
Concrete acceptance test: the complete existing parity/census suite, preexisting frozen/sealed/nonextensible Promises and resource getters; a third observation after second-complete with every diagnostic IO primitive failing; process termination at each state; mapping setup loss/stale identity/wrong writer; prove atomic updates remain visible and cannot fail after success.
Disposition: this supplies a direct parent-side invariant only if the new atomic mapping guarantees are actually established. A normal file, append-only journal, pipe or socket is not an equivalent substitute: a later write can fail after earlier valid evidence.

## Recommendation
Neither option currently satisfies the full bar using only the already inspected/licensed runtime capabilities. Do not exclude the failing ordinary JavaScript states or relax original outcome parity.
If PM commissions another feasibility step, prioritize the atomic-slot option's minimal source/ownership proof: it targets the durable failure gap directly and does not depend on exit-callback ordering. Reject it before implementation if a stable nonthrowing atomic mapping cannot coexist with the exact child command.
The runtime-census option remains smaller in dependencies but has an unresolved final-snapshot boundary and broader raw-output custody. It should not become a fallback based only on an early passing count.
This document proposes no new implementation, runtime/package purchase, native/private run, acceptance or integration. Any next step requires an exact new PM brief.
