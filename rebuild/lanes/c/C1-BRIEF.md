## Deliverable: `rebuild/m3/w6/local/` — the LOCAL-ERA durable client
1. `local-keys.mjs` — device-local key custody for the sealed generations. A non-extractable AES-GCM-256 CryptoKey generated on first run and stored as a CryptoKey object in a SEPARATE IndexedDB database `<databaseName>-keys` (store `keys`, key `active`) so repository.mjs format 1 stays byte-untouched. Exposes `keyProvider` in the exact shape `openRepository` expects. Missing key with an existing generation → state 18 (RESTORE_REQUIRED), never re-keying, never reseeding. Document the residual honestly: P1 (production key custody/recovery) stays BLOCKED for hosted; local-era custody means an evicted/wiped key = restore from the PC port (C2) — the frozen app remains the fallback.
2. `local-era.mjs` — the LOCAL ERA. On enrollment generate: `eraId` (random 128-bit hex), the T2 identity key (32 random bytes hex, used by ops.cjs commitmentOf) and a local authority key; self-issue ONE lease `{lease_id: "local-era:"+eraId, athlete_id, device_id, range:[1, 2**31-1], not_before: enrolledAt, not_after: enrolledAt + 400 days, schema_version: 2, signature}` signed with lease.cjs DOMAIN over the local authority key (so rebuild/client's unchanged lease.check verifies it — no client edit). Keep era material INSIDE the sealed generation at `metadata.localEra` (encrypted at rest under the device key; never in plaintext storage, never logged). Rule written into the module header AND the report: in the local era nothing can refuse an operation, so "Saved" means durably-committed-on-this-phone, NOT authority-accepted; every op carries `lease_id = "local-era:<eraId>"` so a future hosted onboarding can identify and adopt local-era ops (adoption = deferred with hosted sync per DECISIONS:88; not designed here).
3. `local-client.mjs` — `openLocalDurableClient({indexedDB, crypto, databaseName, namespace, athleteId, deviceId, clock, workoutCommands?, projector?})` → `{ status(), enroll(cleanInit?), boot(), execute(command, args), current(), resumeAfterKill(), close() }`.
   - Composition = `openRepository` (local keyProvider; `authorizeEnrollment` = local first-run evidence: store absent AND keys DB absent AND no `enrolled` marker) + `createT2Stage(configProvider)` where configProvider reads identity/lease from `generation.metadata.localEra` + `createBridge` UNCHANGED with `validateCommit` = a synchronous reject-only validator (namespace match, session epoch match, sidecar basis consistent — see 4).
   - `status()` → one of `first-run | ready | restore-required | closed` with the code (STORE_MISSING / KEY_MISSING / T2_INTEGRITY_UNPROVEN …). `first-run` ONLY when generations store, keys DB and marker are ALL absent; any partial presence = `restore-required` (this is the "whole local erasure becomes fresh" witness made as narrow as a browser allows; record what it cannot detect).
   - `enroll(cleanInit)` — the null-lane clean-init on the T2 side: seals generation revision 1 with EMPTY collections for every name in rebuild/client/README.md's collection list, an intact `meta/checkpoint {counts:{ops:0,outbox:0}}`, `meta/device {device_id, athlete_id, seq:0}`, `metadata.localEra`, `metadata.enrolledAt`. `cleanInit` is an optional host-owned object stored verbatim at `collections.derived` (see 4) — the engine-side clean-init state is Track A's, C1 only carries it.
   - `execute(command, args)` for `weighIn | logSet | logSession | finishSession | workout` — result = the bridge's result: `{acknowledged, state, copy, op_id(s), durableRevision, durability}`; Saved ONLY after IDB `complete` (the bridge already does this — do not reimplement; prove it with the early-ack bite pattern from test/workout-bite.cjs on YOUR module, not on client/index.cjs).
   - `current()` = published view clone; `resumeAfterKill()` = the client's resume face (last saved set + unfinished draft) read from the freshly loaded generation.
4. Derived-state sidecar (so the engine's `s` blob can ride in the SAME durable commit as the op): reserve `collections.derived` = `{ basis: {opCount, lastOpId}, value: <host JSON> }`. If the host passes `projector(candidateGeneration, {command, args, ops})` → its return value is written to `collections.derived` BEFORE seal, inside the same repository.commit; on boot the factory returns `derived` and `derivedStale = (basis ≠ actual ops)`; when stale the host must rebuild from ops (rule: OPS ARE TRUTH, derived is a cache; C1 never interprets `value`). The validator refuses a commit whose sidecar basis disagrees with the candidate's ops. If no projector, `derived` is carried unchanged.
5. Browser bundle: `local/browser-entry.mjs` + `local/build.mjs` reusing build-browser.mjs's esbuild config/allowlist (import it or extract a shared function WITHOUT changing build-browser.mjs's output bytes). Output `rebuild/m3/w6/dist/local.js` gitignored like the existing bundle. No new dependencies (pnpm-lock.yaml unchanged, root lock unchanged).
