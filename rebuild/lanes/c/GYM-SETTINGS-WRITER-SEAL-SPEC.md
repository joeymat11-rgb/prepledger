## Invariant and scope
The released settings view supplies raw answers and an opaque editor token to a sealed writer. Drawing cannot mutate cached reads or acquire the settings host, except the exactly pinned public first.settings.lane passthrough. A pending same-writer operation cannot be entered again. Existing payloads, notes and sentences remain unchanged; stale/repeated submissions are silent, and late completion cannot replace a newer editor.

## B. Design contract (UNMEASURED until built and driven)
Use the existing gym-settings-lane as the sealed controller. No new validator, producer, store, clock or persist path. All new state, dispatch, lifecycle, read-detachment and result code below is NEW HAND-WRITTEN WRITER LOGIC (N). Exact helper relocation alone is PURE MOVE (M). Named import/export/call and copy-mapper transformations are DECLARED STATEMENT REWRITES (R). A rewritten writer body is N even when its old expression is retained. These classifications apply to every implementation hunk; a builder must list any unclassified hunk for PM review.

### Entry points and custody
The following signatures are normative design, not a report of existing exports. Internal commands are not returned from the factory. DOM is admitted only to infrastructure binders, never to a command or its result. Tokens are frozen empty objects compared by identity against sealed records; callers cannot construct authority by guessing a number or copying fields.

### Editor and pending state transitions
- Mint only when settingsEditOpened admits the sealed current active lift and known cache. Seed the view's mutable draft with existing draftFrom on the returned latest. No caller-supplied machine, exercise_id, admission boolean or normalized draft enters recordSettings.
- Save accepts only this mount's current editorToken, its captured lift, live registered Save binding and a valid consumed permit. Check again after readRaw and immediately before host.save; capture raw answers into a fresh plain object before yielding. Apply the moved machineFromDraft(raw, heldLift) then acceptable(machine) in the original order. Do not replace machine with acceptable's canonicalization result, sort rows, parse values or add keys.
- Invalidate on matching Cancel, replacement Open, leave, a completed readView showing another lift or nonactive phase, and matching successful Save. A same-lift repaint, row add/remove, refused save or read refresh retains the editor token and its existing error. readView has its own monotonically ordered request ownership; a late read cannot switch the active lift back.
- Save completion always accounts for its original captured lift. On success evict/re-read that lift even if its editor was replaced or left; re-read may update private cache but may paint only a live mount. Only an exactly matching editor may be cleared or receive a refusal. On matching success, capture its current binding, check ownership, retire the editor and deliver saved synchronously without an intervening await; the released mapper compares its held token before clearing. Before any other released onOutcome, recheck ownership; never reuse a captured DOM map to set a later error. Retain onOutcome for the latest binding of the matching editor so a row-add repaint receives its existing refusal.
- Separate settingsPending from workout pending. Preserve optional settings independence: a slow settings read/save does not block Log Set. The owned B.3 subjects have named flags recordSettingsBusy/logSetBusy/finishBusy/forgetBusy/undoBusy, set synchronously and cleared in finally. Additionally retain the old shared workout exclusion for logSet/finish/forget/undo; do not accidentally allow finish while logSet is pending. Settings is outside that shared exclusion.
- Hold recordSettingsBusy through host result and required cache refresh. api.pending returns the last admitted operation, assigned before any callback; an ignored repeat cannot replace it with an already-settled promise. A failure releases the slot and permits retry. The saved result must not be downgraded to a failed write when a subsequent read fails.
- forget takes the shared workout slot through its resulting paint settlement (onOutcome may return that Promise), so repeated advance cannot slip through while its screen is replacing. Its model call is still just saved = null. Record its result as transient; no durable count is added. Always release flags if reading, writing or painting rejects; notification failure cannot retry a completed command.

### Gesture admission, not a listener-wide counter
N: bindSettingsSave and bindGymAction install sealed click listeners that call their private commands directly. The control-to-action mapping is sealed: settings-save; log; primary on complete -> finish; primary on saved -> forget when sealed view.next exists, otherwise finish; undo on saved -> undo. Select exact data-slot/data-action controls inside the current root, require unique matching control, enabled state, currentTarget identity, current binding/context and live mount. Pin event type to click; only an action allowed by the sealed phase can bind. Consume before raw capture. A click on a child icon is valid through its intended currentTarget. Ordinary setup/help/why/back/input/row-edit listeners never get a permit.
N: require event.isTrusted === true for production durable dispatch (including browser-generated keyboard/assistive activation clicks). Keep a private WeakSet of consumed event objects, checked and marked before raw capture, so reusing a trusted event cannot mint another permit. Programmatic click/dispatchEvent, timer, paint, nested repaint, different control and replay of the event or binding get no permit and no write. Do not pass an event, a generic 'inGesture' boolean or an ambient counter into a writer. Binding changes are not authority to invoke a command. Disposing/replacing bindings removes the actual installed wrapper and revokes it even if someone retains that wrapper.
N: admission and raw capture happen synchronously; asynchronous host/producer/readback work stays wholly inside the admitted sealed command. A released callback cannot await and then submit, so there is no normal awaited continuation that is silently rejected instead of painting its refusal.
