# HOTFIX: the deployed page did not boot (`__dirname is not defined`)

**MINE.** In the :185 test-hygiene work I derived `plain-copy.cjs`'s `OWNED` from `__dirname` so the dash guard could be proved RED against a copy of the today directory. `plain-copy.cjs` is a BUNDLED INPUT of the shipped page, and in a browser `__dirname` does not exist: reading it at module scope threw before the first paint and every screen was gone. Found by the N2 builder, not by a test.
**THE FIX** is the N2 builder's exact spelling, taken verbatim from `744c63c` so his branch rebases clean: `const OWNED_PATH = typeof __dirname === "string" ? __dirname : "rebuild/m3/w7-preview/today";`. `typeof` on an undeclared name does not throw, and the fallback is the same four segments, so the build keeps the derived value and the browser never evaluates the read. Attribution is unchanged on the real tree: **117 banners / 33 owned / 0 offences**, `OWNED` still `rebuild/m3/w7-preview/today/`, and `AI_DASH_GUARD_BLIND` still fires for a wrong-depth copy (proved by the plant in `copy.test.mjs`, RED on the copy and GREEN on the tree).

**WHY NO CHECK CAUGHT IT.** Two blind spots that lined up.
1. Under `node --test` the bundle is only ever READ as text. The dash and network guards are static scans; the page is never EXECUTED, so a module-scope ReferenceError is invisible to every Node suite.
2. The msedge checks do execute the page, but `browser-check.mjs` and its five siblings call `startServer()` and never `buildToday()`: they serve whatever is already in `.tmp/w7-today-dist`, which is gitignored and per-worktree. Run on the tip WITHOUT rebuilding, browser-check PASSES, because it was reading a bundle built before :185. Rebuild the tip's own sources into that dist first and it FAILS: `A1 TODAY BROWSER CHECK FAIL - pageerror: __dirname is not defined`. That is the reproduction.

**THE TWO NEW NETS.**
- **(a) the bundle is EXECUTED** (`copy.test.mjs`, `A1 the built bundle EVALUATES with no Node globals`): the built `app.js` runs in a `node:vm` context shaped like a browser, with `__dirname`, `__filename`, `require`, `module`, `exports` and `process` asserted ABSENT, and must evaluate and yield `boot`/`mountToday`. RED on the tip's bytes with the exact production error (`ReferenceError: __dirname is not defined at .../plain-copy.cjs`), GREEN after. It is in `copy.test.mjs` rather than `package.test.cjs` because the B-NTC artifact pins that file ON DISK and a byte of ours there turns `rebuild.yml`'s gate red.
- **(b) the build REFUSES it** (`build.mjs` `assertNoNodeOnlyGlobals`, beside the dash guard): a static scan, before a byte is written, for a bare `__dirname`/`__filename`/`require(` outside a comment, in every module the bundle carries that THIS repository wrote. Attribution is by esbuild banner, as the dash guard does it (109 own modules scanned, 8 vendored skipped), because a vendored module's dead CommonJS branch is somebody else's business and refusing the build for it would be a false accusation; the guard refuses to run if fewer than 20 own modules carry a banner. Exactly one idiom is exempt and only in its own true-branch, `typeof X === "..." ? X : fallback`; an unguarded read one line away is still an offence. RED on the tip's bytes, GREEN after. This one runs on EVERY build, including CI's own package step, so the regression cannot reach a deploy again.

Also fixed here: the plant directory is unique per call, not per process. Reusing one path served the second plant the first's `design.cjs` out of Node's require cache, which surfaced as an intermittent `BUILD-ID-INJECTION FAIL ... appears 0 times, not once` under full-directory load.
