Ruled first by DECISIONS:531 after the independent gate teeth audit R1 (`rebuild/lanes/c/ui-port/GATE-TEETH-AUDIT-R1.md` at 7aede511 on `rebuild/r-cui-gate-audit`; read it whole before touching a file). Branch: `rebuild/c-ui-0-gates`, based on the design of record at 5f4cad0a plus the C-UI-1 round's gate fixes (4f14092e). Nothing on this branch touches `app/`; the pack's prototype is the fixed target the gates are proved against.

- WHY: the audit ran ten forbidden changes through the two gates and seven passed green. C-UI-1 is built and reviewed but cannot seal against these gates.
- DESIGN OF RECORD: `rebuild/m1/approved-2026-09-18/` unchanged. `quality/STANDARD.md` is edited only where it claims a check the code does not perform.
- MAY CHANGE: everything under `rebuild/m1/approved-2026-09-18/quality/` (`gate.py`, `statesheet.py`, `phonesheet.py`, the baselines, a new `teeth.py`, `STANDARD.md`'s check tags and section 7), README sections 1, 3, 4 and 7 of the pack, `.gitignore` for `quality/run/`.
- LOCKED: `app/` (the prototype), the rulings, every other lane file. No dash, readiness word or vendor name anywhere new. No new Python dependency beyond numpy, Pillow and playwright. No absolute path, no Linux-only path.

## ACCEPTANCE (DECISIONS:531, verbatim in substance, then the lane's additions)

1. **Every mutation a to j in the audit FAILS for the stated reason or refuses cleanly** (no crash, no vacuous pass, a report is always written). Including: b1 readiness word; c the sans face swapped for the serif file; d-1 the primary pushed off the 393x852 viewport (a FAIL line, not a Playwright stack trace); e1 primary text between 3.0:1 and 4.5:1; g one changed word in a state's copy; h2 a 60 px shift in a state; i a deleted baseline; j1 and j2 `EARNED_APP` pointed at an empty folder or a non Earned page (exit 2 with a one line refusal naming the URL and what was missing).
2. **The state sheet compares each state against a committed baseline with a stated tolerance and exits non zero on a miss.** Exit 0 only when every render is clean and within tolerance; exit 1 on any problem; exit 2 when it could not run. A missing baseline is a FAIL that names the state, never a silent set. `--accept` is the only way to write baselines; an accept run's report says in its first line that it compared nothing.
3. **Both gates run on Windows and Linux** to completion and write their reports. No hardcoded font path: try a short candidate list per OS, then `PIL.ImageFont.load_default(size=…)`; the sheet labels may look different, the checks may not.
4. **A font check exists in `gate.py`:** sha256 of `app/fonts/earned-sans.woff2` and `app/fonts/earned-serif.woff2` against the values pinned in the script, and the computed `font-family` of one serif element and one sans element per screen resolving to the loaded faces (use `document.fonts.check` or the computed style of a known element). Mutation c must FAIL on both counts.
5. **README sections 3 and 4 and STANDARD.md say exactly what the code does.** Every rule tagged *gate* names a check that exists in `gate.py` or `statesheet.py`; a rule with no code is retagged *eye* or *reviewer*, or gets its check. Section 7 item 5 ("any pixel change outside the intended area fails the run") becomes true. README section 1's counts are the real ones (distinct checks and result rows, both), and no committed report is an `--accept` run.

Lane additions (the audit's N1 to N5 and its section 3, all in scope; the second auditor will run the same list):

6. **Regression FAILS and does not self heal** (`gate.py`): baselines live per platform under `quality/baseline/<sys.platform>/` with an `ENV.txt` recording OS, Python, playwright and Chromium versions of the machine that set them. A missing baseline for the current platform is a FAIL naming the path and the `--accept` remedy. Tolerance, stated in the code and in README section 3 in the same words: FAIL when more than 0.1% of pixels differ by more than 10 levels in any channel, or the mean absolute shift exceeds 0.5 levels; anything else PASS with the numbers printed. The Linux baselines are set on this branch by the builder; the win32 baselines are set on the owner's PC by the lane lead before PR-READY (leave the mechanism ready, do not invent Windows PNGs).
7. **The state baseline** (`statesheet.py`): per state and theme, a small committed record under `quality/baseline/states/` holding (a) the screen's visible text, whitespace normalised, (b) for every visible text bearing element in document order: its text, rounded rect, computed colour, first font family and font size, (c) a thumbnail of the render small enough that font rasterisation does not register (a 1/8 scale greyscale PNG is the expected shape), so the record is platform independent; the whole `quality/baseline/states/` directory must stay under 3 MB. Tolerance, stated in the code and the README: text identical; each rect within 3 px on every edge; colour within 3 levels per channel; family and size equal (size within 0.5 px); thumbnail mean absolute shift under 2.0 levels and fewer than 1% of its pixels off by more than 24 levels. Mutation h1 (3 px) is inside the tolerance and must PASS; g and h2 must FAIL and say which state, which element and which measure.
8. **Clean refusals** (`gate.py`, `statesheet.py`, `phonesheet.py`): `EARNED_APP` at a page without `.screen.is-active .ui` (or without `window.earnedStates` for the sheet) exits 2 with one line and no traceback; the pressed state block and every clipped screenshot survive an element outside the viewport (scroll it into view or record a FAIL for that element); no bare `await pg.evaluate` dereferences a possibly null element.
9. **Contrast** (`gate.py`, `statesheet.py`): 4.5:1 for primary text, 3.0:1 for muted text and for text 24 px or larger, both tiers reachable. Muted is not "colour differs from body": derive it from the pack's own tokens (the colour equals `--muted` or the element carries a class the stylesheet marks muted: `.sub`, `.muted`, `.eyebrow`, `.link`, the status chip text; read `app/app.css` and list the classes in the script). Mutation e1 FAILs, e2 FAILs, the prototype passes with no WARN.
10. **The RIR lock** (`gate.py`): on the workout screen exactly five `.chip` buttons in `#rir` with `data-rir` values `0`, `1`, `2`, `3+`, `unsure` and labels `0`, `1`, `2`, `3+`, `Unsure` (app/app.html:176 to 180), all visible; a dropped or renamed chip FAILs (BRIEF-RIR-DISPLAY).
11. **Rules marked *gate* with no code**: page margin 22 px (every card, button and pill's left edge at 22 px, right edge at width minus 22, on all three sizes), the 14 px card inner edge and the 13 to 14 px icon inset, the bottom safe area (the last element of the fixed stack clears `env(safe-area-inset-bottom)` or 24 px), serif versus sans assignment (names, numbers and headlines resolve to Earned Serif; everything else to Earned Sans; list the selectors), the × rule on every set string not just `#log-label`. Code each, or retag it honestly in STANDARD.md with the reason; either is acceptable, silence is not.
12. **Viewports**: copy, type, radii, contrast, the × rule and the font check run at all three sizes; seams, regression and columns at 393x852 only, and README section 3 says so. The motion check runs with reduced motion off as well as on: with the embers hidden nothing moves, and any CSS transition or animation on a non canvas element FAILs under both settings.
13. **`quality/teeth.py`**, the executable mutation list: copies the pack to a scratch directory, applies one mutation at a time (every row of the audit's table, a to j2, plus the lane's: a dropped RIR chip, a serif element switched to sans, a card moved 6 px off the margin), runs the gate or the sheet against the scratch copy, and asserts the exact refusal line (or exit 2) for each; prints a table; exits non zero if any mutation slips through. Runtime under 25 minutes on this machine. The second auditor runs it, then does the same by hand.
14. **`quality/run/` is untracked** (gitignored) and the README says the evidence of a green run is the PR-READY line and the reviewer's own run, not a committed report. The six baseline PNGs already in `quality/baseline/` move to `quality/baseline/linux/` if they still match this machine's render (they will not; set them fresh with `--accept` and say so in the commit message).
15. Exit codes and summaries for both gates: `0` green, `1` FAIL present, `2` refused. The summary line counts FAIL, WARN, PASS and (on accept runs) SET separately. WARN is used only for the type scale and the spacing scale, which are advisory by STANDARD.md's own words; nothing else WARNs.
16. The prototype itself passes both gates on Linux with 0 FAIL after the fixes (the prototype is the design of record; if a new check finds a real defect in it, record it as an open question in the package rather than editing `app/`, unless it is a one line copy or attribute fix that the boards agree with, and then say so).
