Existing local-host key/observation fences and W5 source/recovery APIs stay unchanged.

## B. Mixed history without rewriting chronology

Native order remains the existing same-generation causal DAG at W0; a cycle, missing parent, unresolved Start, concurrent ready local roots or edited original refuses its existing order code. Preserve every op_id, commitment, parent, effective tuple and capture byte. Preserve imported sessionLog verbatim and its internal legacy order; dates label records but never create a native edge, accepted tie or cross-format order proof.
Two separate cases: genuine hosted source+postactivation descendants continue through the UNCHANGED hosted profile; local imported+pre-import native records require proposed earned/local-source-order-map/v1. A receipt, codec hash, import commit time, same-athlete confirmation or B3 merge result is insufficient for that new map. An empty legacy/native side is only a control, not the S3 positive witness.
Available T evidence proves each side's membership and native causal order, not their relative chronology or duplicate-workout identity. Proposed narrow positive lane requires a NEW explicit factual assertion, subject to PM/owner judgment: one selected immutable legacy block precedes one named included native root, all native Starts descend from that root, and the block contains no workouts already represented in the native group. No automatic interleaving, same-workout deduplication or guessed legacy-to-native lift remap.
Prospective UI, after separate athlete/file confirmation: show source fingerprint/member count and the exact native root/group (dates are labels), then ask "Did every workout in this file happen before this first Earned workout, with none already recorded in Earned?" Yes records that specific assertion; No or inability to confirm leaves ORDER_EVIDENCE_REQUIRED and application pending. General import/PM authorization is not the answer. No real assertion is collected by this design task.

## Atomic publication and portable replay

Phase1 reuses C2b importBundle/import-custody: authenticated immutable named originals and import entry commit, application pending; nonempty local ops/outbox/captures/drafts remain exact. A seeded zero-op cache is not qualification. Name/material conflict refuses; an inactive custody orphan is retryable by exact identity, not overwritten (import-bundle.mjs462-529).
prepareSource returns an inactive handle only after complete source reproduction, local validation, family folds, Q/M and programme/context proof. assertCurrent rechecks installation/session/source and repository revision/token around EVERY await, including hashing/decryption and original-capture reads. An in-memory interpretation/profile change also invalidates the handle even without an op write. Capture the whole immutable candidate once before asynchronous sealing.
Phase2 source-commit uses existing repository.commit CAS, not a second importer/store: atomically retain originals+all local collections, append immutable local selection/assertion/evidence, set active local-selection pointer, write projection+Q/M and set the matching application-complete marker. Mark only the selected import applied; other pending entries stay pending. Never call standalone markImportRebased as proof. The synchronous reject-only transaction guard checks the captured session/semantic epoch; repository revision AND token reject concurrent durable changes (repository.mjs215-307).
Marker binds input revision/token/Q to resulting committed revision and selected source; after commit, reload/rebind the new handle to that actual durable generation before publishing. Semantic hashing excludes derived caches/the marker itself to avoid self-reference, while covering every governing source/input/interpretation. Any later save invalidates this projection by basis mismatch or atomically provides its requalified successor; stale guidance is withheld without blocking factual save.
Crash controls: before phase1 no active change; after custody but before import commit inactive original only; after phase1 pending; phase2 abort exposes old pending state, commit exposes whole completed state. Lost acknowledgment reconciles exact durable selection/marker after reload without duplicate import/assertion. Reopen authenticates and reproduces from retained material/current folds before guidance; cached state/old opaque handle alone never suffices. Rollback appends a selection, retains newer ops and former sources, then recomputes Q/M; never restore an old whole-store snapshot.
Extract one pure prepare/replay core with injected exact UTF8 bytes, SHA256, HMAC/canonical commitment checks, strict parser and lossless JSON equality; retain existing Node wrappers and browser adapter. Use existing pinned primitives/WebCrypto, no dependency or domain substitution. Identical engine/clock/source/local inputs must yield byte-identical candidates and identical folds/Q/M/order/refusals in Node22 and browser; actual platform metadata is truthful and separate from semantic hashes, never fabricated process.versions.node. No Buffer/Node crypto/util/process leaks into the phone graph.
