## Existing shapes and actual guarantees
- Opt-in input is `{user, accepted, accepted_at, screen_version, wording}`; `user` must exactly equal `joe` or `dad`, and `optIn.user` must equal the supplied user (`tools.cjs:984-1004`). No case folding or guest path exists.
- `accepted` must be boolean `true`; every listed member must be present, non-null and nonempty. `accepted_at` need only pass `Date.parse`; `screen_version` has no type, recognized-version or freshness check (`:998-1005`).
- Wording is converted to a string and checked for four word groups: phone; audio/voice; text/transcript; leave/send/goes/go to. This is a lexical transfer-disclosure check, not proof of the screen actually shown, provider naming, an affirmative sentence or an authentic consent event (`:1006-1014`).
- `verifyOptIn` returns `{ok:true,code:null,reason:null,user}` or `{ok:false,code:"COACH_OPT_IN_REQUIRED",reason}`. Unknown users currently share that refusal code. Nothing signs, persists, expires or revokes consent (`:989-1014`).
- Cap schema requires `{provider, account_label, cap_usd_month, cap_usd_session, per_minute_usd, verified, verified_at, verified_by, evidence}`. Optional `notes` is allowed; the schema's `_note` is for the shape example only. `additionalProperties:false` is declared (`cap.schema.json:6-28`).
- Runtime requires all cap fields above (`verified` is checked separately), three finite positive numeric amounts, `verified === true`, parseable nonfuture verification time no older than 30 days by default, and session cap no greater than month cap (`tools.cjs:927-973`). It scans the serialized receipt for credential shapes and rejects every underscore-prefixed field, including `_note`.
- Runtime cap validation does not invoke the JSON schema: non-annotation extra members and non-string descriptive members are not generally rejected. No provider allowlist, exact ISO grammar, required owner identity, account-key binding or $50 monthly maximum is checked. The schema's account-label restrictions are descriptions, not runtime checks (`:938-973`).
- A good cap returns `{ok:true,code:null,reason:null,capUsdMonth,capUsdSession}`; absent/invalid records return `COACH_COST_CAP_ABSENT` / `COACH_COST_CAP_INVALID`. This attests a receipt's shape and claimed freshness; it neither visits billing nor proves an account hard stop exists (`:938-973`).
- `startLiveSession({cap,now,optIn,user})` checks cap first, consent second, then always returns `started:false` and `COACH_NO_LIVE_ADAPTER`. No network, token mint, active session, counter, minute timer, charge meter or shutdown is implemented (`:1019-1024`).

## Reuse without changing the established meanings
- Keep exact named-user ids and the five opt-in members; preserve the actual reviewed wording with its screen version. A relay authentication credential must be separate from `user` and must never be confused with consent.
- Keep the cap receipt members and units; `account_label` remains a human label, never a provider account identifier or a key. Keep the receipt server-side; neither billing amounts nor long-lived provider credentials belong in a token response.
- Keep fail-closed cap and consent ordering, no override, and the example-receipt rejection. A separately reviewed live relay needs an explicit admission result; treating `COACH_NO_LIVE_ADAPTER` as an unconditional success would erase what the current test proves.
- Keep the harness-owned spoken confirmation flag, closed tool declarations, same-turn field/unit traceability, charter check and discard-before-speaking rule. The adapter brief allows at most six tools and one answer draft per turn, last two conversation turns only, and minimal tool context (`model-adapter.md:13-80`).

## Amendments needed before either lane builds against the handoff
- AUTHENTICATION: a caller can currently claim either named string and submit a matching invented opt-in. Add verified enrollment/authentication binding to exactly one named user; CORS/origin checks alone do not supply that identity. Specify enrollment, revocation, expiry and retry behavior without sending a provider key to the phone.
- CONSENT: define exact accepted screen versions/wording, strict member types, an admissible acceptance timestamp and revocation behavior. Preserve the five-member receipt; bind it to the authenticated user. The present regex cannot establish that someone saw or agreed to the words.
- NONCE: section 4 says the client nonce is echoed but omits it from `{token,expires_at,session_minute_cap,session_id,provider,model}`. Add the echo, and distinguish response matching from server-side duplicate/replay protection.
- ENFORCEMENT: distinguish token redemption expiry from live-session lifetime. Section 4's stopping token minting after the minute cap cannot itself stop an already active phone-to-provider stream. Name the actual enforced shutdown mechanism and same-session renewal accounting; the provider-mechanism study must settle this.
- BUDGET: choose a minute cap for the wave-one gym session, then account for all provider charges and concurrent sessions. `cap_usd_session / per_minute_usd` alone is a voice-layer estimate, not evidence of total spend or the owner's $50 hard monthly cap. The root's provider research must verify that cap rather than copy launch pricing from the old brief.
- STATE: `DECISIONS:134` says stateless/stores nothing, while C's proposal allows per-user session/minute counters. Counters, replay rejection and reliable concurrent admission require an explicit retention/state contract. Seek PM wording that names permitted metadata and its lifetime; never broaden this to audio, transcript or athlete data.
- ERRORS: section 4 adds `COACH_USER_NOT_NAMED`, `COACH_SESSION_CAP_REACHED`, `COACH_CAP_NOT_VERIFIED`, `COACH_RELAY_UNAVAILABLE`; these are not existing `tools.cjs` return codes. - ORIGINS: the relay origin remains unspecified. Freeze it only once the deployment target is concrete; C needs exact relay and provider stream hosts for CSP/CORS. A promise of one relay host is not permission for arbitrary provider or redirect hosts.
- SPEECH: the adapter must inspect a drafted answer before any untraceable audio reaches the user (`model-adapter.md:13-31`). Direct provider audio streaming does not prove that interception exists.
