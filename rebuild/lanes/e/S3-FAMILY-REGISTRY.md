## Exact interpretation rules that prevent false coverage

F1 uses each reading projector record's local result after identity/status/target validation; the sorted display-only reads() array loses effect detail and effective-hour provenance. Reconstruct from immutable baseline every time, respecting existing engine refusal and order rules. The registry introduces no new recency/default-hour rule.
F2 N1 whole-answer replacement uses only authenticated records from this installation/profile and the existing same-device read order; preserve the replaced operation as provenance. Reject unexplained sequence reuse/concurrent claims rather than use op-id spelling to invent authority. Source/native same-day overlap needs a separately ruled winner, so remains unresolved here. The schema1 branch has a named fold but no demonstrated current Today producer; no new steps UI or schema1-to-schema2 migration is licensed.
F3 reconstructs current local factual values and original captured layout; preserve original effective tuple, completion semantics, effort unknowns, removed/skipped slot provenance and source memberships. Never replay completeSession, plan proposals or historical outcomes as commands. New local_source_basis travels through actual Start/continuation/resume; old captures are validated under their original profile, not rewritten.
F4 agreement checks exact source/setup split coverage and every exercise's id, day, mg, sets, hi, inc and explicit steps, plus tags/secondary/priority values wherever a current consumer uses them. Distinguish current engine-derived working weights from configured ladder/set semantics; an existing admitted recorded change must explain divergence or it is unresolved. Do not equate display names, re-slug IDs or reset w/last/history via clean-init.
For each native captured slot, engine-history resolves earned/captured-lift-layout/v1 and checks producer/basis, ordered slot count, logical_set_slot, lift_lineage_id, unique positive position and original captured effort/unit contract (engine-history.cjs62-80). Resolve those IDs to the SAME programme exercise and registered local/legacy correspondence; no guessed remap. Positive: exact identity/layout agreement with historically different performed loads. Negative: same display label but different identity, swapped positions, duplicate slot or altered captured producer/basis. M preserves the shared original sessionLog reference.
F4 settings are strings/cues only: machineOf validates shape, latestFor selects effective date then its existing local log order. Q must bind both exact current result and all contributing originals; profile-aware validation occurs before generic dead/rejected filters. A numeric-looking cue never becomes load/sets/RIR or a plan change.
F5 check-in model normally allows one record per day and reads only that day's rows; its readback is not a general correction conflict solver. Preserve multiple originals; unexplained competing current records or unregistered effect targeting a check-in is unresolved rather than inventing latest-wins authority. Existing accepted N2 must later name exact dated-night write/correction/source context before dispatch expansion. Confirmed old-night provenance cannot become a second measurement.
F6 has deliberately no new engine-effect adapter. A retained-only historical note is not itself a qualification failure when it claims no current effect; an unexplained current plan request IS. Every unrecognized profile/class/effect is retained and explicitly flagged, never silently dropped from the closed registry or admitted by a default branch.
