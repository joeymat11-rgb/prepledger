Authority bridge: one consistent D1 read batch loads the athlete and every ownership/dependency/drain input with a revision; run the synchronous core on a staged cache. An atomic write batch first asserts that revision through a failing constraint, publishes all effects and increments it. Initially use a global revision to cover foreign ownership dependencies; retry stale work from a fresh snapshot. Enforce unique athlete/device/sequence, athlete/op identity and log-position keys; return no successful disposition before durable commit. [D1 batch semantics](https://developers.cloudflare.com/d1/worker-api/d1-database/).
Browser bridge: await load, crypto and HTTP outside the synchronous core; stage candidate model/store changes. Commit operations, outbox, sequences, inbound receipts/dispositions/rejections, frontier, keys, leases/high-water and checkpoint in one IndexedDB transaction with a stored revision check. Publish/acknowledge only after transaction completion; abort discards uncommitted local writes and retains typed values. For a known authenticated rejection, failed persistence must retain a recovery fence and block truth paint until disposition + rejected ledger + outbox removal commit atomically and idempotently; never restore that rejected contribution by discarding the candidate. Preserve this fence across recovery/relaunch under the sheet's integrity contract. A Promise from today's synchronous `backend.commit()` does not fix early Saved (`client/store.cjs:68–76`, `client/index.cjs:144–148`, runtime:608–615).

Persist that knowledge across relaunch; recheck before the commit cut; a new token alone cannot restore lost enrollment/keys. Mere session expiry on an enrolled/decryptable device is **11**: pause sync, permit valid leased logging. Missing/evicted/corrupt store is **18**: block truth paint and prove recovery/first enrollment remotely; empty storage is not proof of first use. Unprovable clock continuity is **20**. Existing material follows the ratified recovery/erasure contract, not a blanket retain/delete policy (runtime §B 11/17/18/20).
Crypto/auth: replace authority HMAC test signatures at the declared boundary with pinned **P-256/SHA-256** public verification, including canonical bytes/signature encoding vectors. Preserve operation HMAC, identity, domain and canonical contracts. The phone gets authority verification keys only. Authenticate receipts, pulls, snapshots, leases and challenge-bound fresh server time before client APIs. ## 4. Risks, ranked, with concrete mitigations

1. **False Saved or silent loss:** crash both staged bridges at every boundary; compare reopened bytes and outbox, not live counts. Run clock continuity separately on day one; fail closed with state 20 when proof is unavailable. Keep the idle origin pinned and untouched; any survival-relevant storage change needs a qualifying new soak. [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/) does not guarantee survival.
2. **Forged authority or cross-account access:** public verification only on phones, authenticated scope on every route, parameterized scoped SQL and real two-athlete hostile requests. Race independent Worker invocations including foreign dependencies; no in-memory lock can protect their shared database.
3. **Port/restore erases later history:** immutable import generation plus checkpoint/replay; synthetic interruptions before private use. Restore encrypted export into a separate database and isolated account/environment, preserving signed identities while changing only authorization mapping. [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) restores in place and cannot supply that clone.
4. **Engine delay or compatibility mistaken for correctness:** dated checkpoint; I1 proceeds but M3 remains open. Pin both M2 gates and owner-ratified defect outcomes; use a private phone-export projection comparator as well as the existing census. A rule conflict gets a red witness and owner ruling, never a silent change.
5. **Cost warning mistaken for a stop:** accepted residual exposure remains real. I sets CPU ceilings, authenticated admission/rate limits, bounded retry/backoff and an operator pause; prove retryable refusals preserve outbox and never become false terminal dispositions. Include billed rejected traffic, storage, backup and logs in the meter inventory; record calibrated numeric limits before port. No unbounded alert-test burst.
6. **Wrong region or account configuration:** create with `us`, inspect the returned database configuration on the intended account before any real data, and keep exports in the approved location. No `wnam`/`enam` hint substitution. Verify Clerk production email recovery and DNS with synthetic accounts before private sign-in.
7. **Recovery depends on one machine or the owner repeatedly chasing tasks:** commit a runbook, store encrypted recovery material off that machine, rehearse from a clean second machine/account, and let C maintain one dated action list. Owner appointments include both phones, pressure protocol and final idle readback; missing hardware remains a named blocker.
