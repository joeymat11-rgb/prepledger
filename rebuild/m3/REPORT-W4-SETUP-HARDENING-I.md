## 0. Review findings addressed in this revision (Astra, on head 435f145; all five fixed)
1. **Exact-value ownership at cleanup.** Cleanup compared the stored value by marker PREFIX (`-like`), so another attempt's value with the same prefix could have been deleted. Now `Remove-OwnedTempVar` removes a variable only when its current value is `-ceq` the FULL value this run wrote; anything else is `foreign-value-not-removed`. Negative test added: same-prefix / different-value → NOT deleted.
2. **Cleanup after a write that landed and then threw.** `$written` was set only after `Set` returned. Now `$attempted` is set BEFORE `Set`, and `finally` always runs the exact-value cleanup. Tests added: side-effect-then-throw (value landed, exception thrown → outcome `set-failed` AND the landed value is removed), cleanup throw → `cleanup-failed`, read-back failure after write → `unverified-readback-failed` / `cleanup-unverified`.
3. **No caller string is ever echoed.** Unknown-argument and refused-name messages interpolated the raw argument (a misplaced secret would have been printed). All messages are now FIXED sentences; only allowlisted names or generated `EARNED_*` names appear. Sentinel no-echo tests added for the parser (unknown argument, bad NAME, bad HASH) and for `Invoke-StoreSecret` with a refused name. The interactive refused path prints the same fixed sentence.
4. **Fresh intended-process DUMMY proof before any real token.** New owned workflow: `--arm-fresh-proof` writes `EARNED_FRESHPROOF_<random>` (collision-checked, bounded tries) with a dummy marker value and prints its NAME and the SHA-256 of the value; in a FRESH process `--verify-fresh-proof NAME HASH` proves that process inherited exactly the armed value (`not-visible-in-this-process` and `process-value-differs` are truthful failures; a foreign value is never touched); `--cleanup-fresh-proof NAME HASH` removes it only on an exact hash match. Double-click wrapper `store-secret-freshproof-arm.cmd`. SETUP-TOKEN §3 now orders: self-test → fresh-process proof → token → fresh reopen → `whoami` (a SEPARATE authentication proof). No value or length is ever printed; collisions, exhaustion and cleanup failure keep the self-test semantics.
5. **Minimal, isolated child environment for the launcher tests.** The end-to-end tests no longer inherit our environment. The child gets a built-from-scratch env: platform essentials only, `HOME`/`USERPROFILE`/`APPDATA`/`LOCALAPPDATA`/`XDG_*`/`TMP*` pointed at a disposable temp directory, no credential-shaped key at all (asserted; `CLERK_SECRET_KEY`, `CLOUDFLARE_*`, `GH_TOKEN` explicitly absent), and the proxy variables set as a **proxy tripwire** — a fail-fast canary for clients that honour proxy settings, NOT universal network interdiction (stated in the test and here).
