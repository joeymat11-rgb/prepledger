## 1. Scope, ownership and earliest observation

Current acceptResponse receives a caller-owned response before guard.run (public-client118–128,154–157); execute/reopen reach permissionNowIso at82–85 without that guard. exchangeServerTime surrounds request creation at163–177. A guard around the trusted sink alone cannot protect earlier status/header/parser/UI/clock knowledge.
**Proposed owner profile:** one same-origin Web Lock semantic owner per authenticated installation namespace. It alone holds the private durable-client instance, verifier, permission evaluator, token/response parser and transport callbacks. Lock naming uses the exact namespace through a reviewed collision-free encoding; that encoding and supported-browser behavior remain binding-review items.
Other enrolled contexts forward bound intents through owned MessagePorts; they cannot directly invoke these private dependencies. Each intent carries immutable scope/session references, a fresh intentId and its captured input. Responses bind the same intent/scope; stale delivery cannot paint or clear another account's draft. This is a proposed coordination profile, not an accepted restriction of tab/PWA support.
No wall-time lease, heartbeat silence or timeout steals a lock. A paused owner is not a dead owner. After actual lock acquisition, a successor authenticates the stored pair and resolves inherited obligations before exposing truth. Lack of an owner/answer preserves the draft and supplies no success; its exact waiting UI must satisfy the existing concurrency contract before adoption.
The owner keeps network waits outside the short local stage/commit queue. A pending nonnegative network child does not itself forbid a separately permitted local write. Such a write preserves that child's OPEN root. Avoiding a permanent OPEN-per-session guard, mandatory lifetime network connection and automatic bounded-restart refusal is a REQUIRED BUT UNPROVED property: pre-arming continuously available UI controls can violate it, as the crash comparison below explains.
**Proposed auth profile:** no Clerk JS import in the enrolled offline context; use explicitly owned native-fetch requests for the ruled email-code flow and token/session actions. This excludes that SDK's timers/channels by composition, not by polling:false/touchSession:false/off. Actual FAPI request/cookie/challenge and W5 JWT bindings remain OPEN; this document does not implement them or assume a quiet SDK mode.

Before any such cut the matching root/child must already be durable. Full raw data may be held opaque, but withholding a comparator does not erase knowledge already delivered to application code.

## 2. Proposed closed proof shapes

All new K1 wrapper/descriptor/capture shapes below are proposed version1 validators, not currently accepted production validators. Their unknown/missing fields, duplicate decoded keys, unexpected types, nonfinite/unsafe numbers and unsupported versions refuse18 before truth. These new field allowlists do NOT replace inherited W5/T3 signed-record validators: retain every original signed field and use the pinned existing contract, including its permitted extras. No object coercion. Full proof bytes remain encrypted in the existing frame body; its existing kind/version/digest/bytes envelope and strict parser remain unchanged.
Serialization proposal: UTF-8 JSON.stringify of closed objects constructed in the field order shown, no whitespace/newline, strings restricted to Unicode scalar sequences. IDs are32 lowercase hex characters from16 fresh random bytes, checked for collision in retained scope; they are identities, not cryptographic security budgets. References are lowercase64-hex digests or explicit null where allowed. Revision fields are positive safe integers. Arrays are dense; child IDs are unique and sorted by ASCII ID; duplicate memberships refuse.

### 2.6 Protected auth records and decoder joins — proposed, not storage permission

These exact record shapes refine §2.4 headersRef/bodyRef and bind the §2.5 response unions; they do not grant custody or dispatch authority. The pinned strict-json.mjs parser accepts byte input with fatal UTF-8 and a visible BOM (12–21), rejects duplicate decoded keys (97) and nonfinite numbers (66), then returns JSON.parse output (114–116). It does not prove safe integer precision or scalar-only decoded strings. Selecting it for AUTH body parsing is a proposed adapter decision; provider schemas and W5 JWT verification are unchanged. All schema/decoder behavior below is review-required and NOT RUN; the original12 manager acceptance groups in §5 keep their existing inventory/status.

Propose all new records as the existing exact frame envelope {kind,version,digest,bytes}, kind=recovery, version=1. The bytes field is canonical unpadded base64url of the full §2 closed ordered JSON payload's UTF-8 bytes; digest is its lowercase64-hex SHA-256. This matches frame-repository.mjs9–13,39–45; inner body/header byte fields are independently encoded, not confused with the outer bytes field. Each record retains a complete payload and recomputed envelope digest. Protocol→kind is checked; a valid digest with a different kind does not pass. This assigns proposed kinds only to the following three concrete wrappers and parser profile; other profile/owner/session/custody kinds remain OPEN.
Every header/body/parse record begins, in order, {protocol,rootId,childId,scopeRef,producer,requestId,profile,attemptRef,custodyProfileRef,...}. All these fields are required/non-null; producer=AUTH_EXCHANGE; profile=earned/k1/auth-opaque/v1. K1 IDs (including captureId below) are32 lowercase hex characters; proof references are64 lowercase hex characters, with null only where expressly allowed. rootId/childId/requestId/profile/producer must match the originating raw and child; scopeRef equals the attempt's fromScopeRef; attemptRef equals that child's binding.basisRef; custodyProfileRef equals the complete attempt descriptor's custodyProfileRef.
Compare those bindings through the originating immutable root/child version, not an unrelated current UI selection. Later root versions still retain the original obligation. owner/session/device identity is reached through attemptRef and must satisfy its actual reviewed profile. Missing/mismatched bytes fail integrity before truth; a stale positive cannot move into a new owner/account. Independently learned negative evidence stays scoped to its original obligation.
No new scope/owner counters or target-scope authority are created by these wrappers. Even CONTEXT_SWITCH:SCOPE_BOUND cannot re-home a header/body/parse record. These schemas cover AUTH_EXCHANGE response data only; they do not create a context-switch body or an auth-bootstrap namespace.

#### Header and body records

Header record, after common fields: {captureId,response,entries}; protocol=earned/k1/auth-headers/v1. captureId is a K1 scoped ID minted once for the owned returned-response capture, never reused for another response/request; it is an identity, not evidence of origin. response is exactly {urlUtf16leB64,type,status,redirected}, with the exact §2.4 browser-observable types. entries is a dense ordered array of exact {nameUtf16leB64,valueUtf16leB64} records, including an empty array when no header entries are visible.
Each header string is canonical unpadded base64url of its exact UTF-16LE code units: decoding must yield an even byte length; re-encoding must equal the input; decode without replacement, normalization, case folding, sorting or deduplication. Preserve empty values and observed iteration order. This is the browser-visible Headers sequence, not a claim to reconstruct original wire duplicates/casing or inaccessible cookie headers.
Header decoding must compare response fields byte-for-byte/value-for-value to the raw AUTH_HTTP response that references it, and compare capture ownership through the selected live-source binding. Constructing a matching record from an arbitrary Response object cannot prove the request origin/delivery path. Failed/incomplete header enumeration supplies no valid complete header record; it cannot become an empty sequence or erase already learned information. The existing OPEN obligation survives. No decoder reaches out to DOM/fetch, invokes supplied getters or accepts externally supplied mutable parser objects as evidence.
Body record, after common fields: {captureId,headersRef,extent,byteLength,bytesB64}; protocol=earned/k1/auth-body/v1. headersRef is nonnull. For a raw capture referencing this body, auth-body.headersRef must equal raw.capture.response.headersRef exactly; resolving some other header record with matching common values is insufficient. auth-body.captureId must equal that exact referenced auth-headers.captureId. extent is COMPLETE or PREFIX. byteLength is a nonnegative safe integer equal to the exact decoded byte count; bytesB64 is canonical unpadded base64url of uninterpreted bytes. Re-encode equality is required; no TextDecoder, JSON reserialization or string coercion can alter the retained body.
COMPLETE permits byteLength=0 and bytesB64="". PREFIX requires byteLength>0 and means exactly the bytes delivered from the beginning before the read failed; it never asserts EOF, a total size, a valid complete message or a safe retry. Stream capture must copy actual delivered bytes in order, not concatenate an invented missing suffix. Ownership/delivery proof is still required; a matching hash cannot demonstrate completeness.

| raw.capture.response.bodyState | raw.capture.response.bodyRef | Record requirement and parser eligibility |
|---|---|---|
| UNREAD |null | No body bytes observed by this capture; no body record and no parser run. Null does not mean empty response. |
| COMPLETE |nonnull | Full auth-body record with extent=COMPLETE, including a complete empty body. EOF/completion is an owned observed cut, not inferred from valid JSON or Content-Length. Only this case is eligible for body parsing. |
| READ_FAILED, no observed bytes |null | No retained prefix exists; no parser run. Do not fabricate an empty COMPLETE body. |
| READ_FAILED, observed prefix |nonnull | Full auth-body record with extent=PREFIX and exact nonempty prefix; no parser run, even if that prefix happens to be syntactically valid JSON. |

headersRef is nonnull for every AUTH_HTTP response. These records may be constructed only after the relevant actual observations; they cannot establish the prerequisite pre-observation durable arm. No-response AUTH_TRANSPORT_FAILURE carries no header/body record. A returned response whose body later fails stays AUTH_HTTP/READ_FAILED; it cannot be relabelled no-response to erase learned headers/status/prefix.
Each new raw capture phase is a new immutable raw proof referring to its exact header/body records; published UNREAD/PREFIX/history bytes are never overwritten or erased by a later capture. This is not permission to continue reading after failure, reconstruct a prefix from a different request or merge retry responses. Live continuation and retry ownership remain separate K1 producer contracts.

#### Parser result/error lineage

Propose parser-profile payload {protocol,sourceSha256,exportName,inputKind,resultKind}; protocol=earned/k1/auth-json-parser/v1; sourceSha256 is exactly the strict-json pin above; exportName=parseStrictJson; inputKind=UINT8ARRAY; resultKind=ECMASCRIPT_JSON_VALUE. The proposed integration requires an explicitly reviewed built-in dispatch selector, not arbitrary source loading by a stored hash/name. Profile uses kind=recovery/version1. A future changed parser needs a separately reviewed profile; an old receipt is not reinterpreted by the new parser.
Parse record, after common fields: {rawRef,bodyRef,parserProfileRef,result,errorCode}; protocol=earned/k1/auth-parse/v1. rawRef and parserProfileRef are nonnull. bodyRef must equal that exact raw.capture.response.bodyRef, including null where applicable. rawRef must resolve to a K1 raw proof with protocol=earned/k1/raw/v1 and raw.capture.tag=AUTH_HTTP from the same originating obligation; body's header/capture/common fields must match whenever bodyRef is nonnull. The parse result is reproducible from this exact raw/body/profile, not caller-supplied parsed JSON or an unbound boolean.
result is NOT_RUN_INCOMPLETE, PARSED, PARSE_ERROR or ENGINE_FAILURE. NOT_RUN_INCOMPLETE requires raw.capture.response.bodyState!=COMPLETE and errorCode=null; bodyRef follows the matrix above. PARSED requires raw.capture.response.bodyState=COMPLETE, nonnull bodyRef and errorCode=null. PARSE_ERROR requires that same COMPLETE state and errorCode exactly one of STRICT_JSON_UTF8,STRICT_JSON_SYNTAX,STRICT_JSON_NONFINITE,STRICT_JSON_DUPLICATE_KEY reproduced by the pinned parser; this is a mechanical observed-code classification, not proof of invalid provider bytes. ENGINE_FAILURE requires that same COMPLETE state and errorCode=PARSER_UNAVAILABLE; it covers an unexpected failure that escapes the parser's existing catches and is never evidence that the provider sent invalid data.
The five explicit error.code strings emitted by parseStrictJson are STRICT_JSON_UTF8(19), STRICT_JSON_INPUT(20), STRICT_JSON_SYNTAX(24), STRICT_JSON_NONFINITE(66) and STRICT_JSON_DUPLICATE_KEY(97). STRICT_JSON_INPUT is an adapter defect for this mandatory byte-input profile, not a provider parse classification. PARSER_UNAVAILABLE is the proposed adapter's finite tag, NOT an exported parser error string. The parser maps every failure inside its TextDecoder try to UTF8, and every final JSON.parse failure to SYNTAX; its string-decoding JSON.parse catch also maps to SYNTAX. Native/resource failures caught there are not distinguishable from those codes. Even repeated matching codes do not prove every failure is input-caused or that every runtime failure becomes ENGINE_FAILURE. This proposal does not change the parser. Do not stringify or persist arbitrary exceptions, stacks, partially decoded content or parser-produced paths. Map only the pinned parser's recognized finite error code; all other failures remain unavailable. Runtime persistence failures stay separate K1 storage outcomes, not parser success/failure.
On replay, first authenticate complete records and bindings, then reproduce eligible parsing over a privately owned byte copy. PARSED is accepted as a mechanical receipt only when replay parsing succeeds; PARSE_ERROR only when the exact whitelisted error recurs. Do not rerun a parser for NOT_RUN_INCOMPLETE. ENGINE_FAILURE records a failure in that execution, not a deterministic invalid-body verdict; it cannot close an obligation. A later successful retry/replay produces new evidence under the existing K1 resolution rules and does not rewrite the earlier record.
The actual parsed value is derived in memory from the bound body; no second stored object/text/result hash is introduced. It preserves the pinned parser's own-property/-0/finite-number/string behavior, not original JSON formatting or exact arbitrary-precision numbers. The original bytes remain authoritative. Validation must separately enforce any schema/domain field constraints before use; PARSED is neither provider authentication, schema conformance, standing, completed task, verified JWT nor permission.
This draft does not add schema-valid flags or an effects shortcut. A future outcome/effects validator must bind this exact raw/body/parser and the complete selected provider schema/rule, while retaining the full original response and its error/session context. The actual outcome/effects payload/reference join remains OPEN; a parser receipt alone cannot discharge the child or authorize T2.

## 3. Proposed API and transition requirements

The manager privately exposes beginObservation(binding), dispatch(handle,producer), capture(handle,raw), resolve(handle), beginClose(rootId), finalize(context) and releaseOwner(). Handles are scoped, candidate-bound capabilities; the same request may retry only under its original immutable identity and a separately recorded attempt. No public alreadyArmed flag or unowned callback can bypass dispatch.
beginObservation first authenticates the pair/current scope and builds the full root/child proof. Commit OPEN with full-pair CAS and await transaction complete before enabling the producer. Arm failure triggers zero controlled requests/samples/intent controls; retain input and return3 unless an independent stronger fault is already known. No knowledge-survival claim is made before that commit.
Adding a child requires its durable membership before dispatch; concurrent membership changes require restaging from the new complete basis. ARMED and DISPATCHED phases describe durable evidence, not proof of a maximum runtime phase. Children never allocate operations or allowance slots merely by existing.
capture preserves full relevant evidence before positive semantic use, while immediately latching independently learned17/19/20 and invalidating affected candidates. Capture/outcome-write failure leaves the already durable OPEN obligation. A failed raw write is not permission to declare the event unobserved or fall back to a positive old view.
resolve evaluates the exact retained raw/basis/rule version and persists complete consequences atomically. Authenticated rejection must commit rejected ledger, disposition and outbox change together and idempotently; accepted facts cannot be removed because a reply was lost. No ordinary trusted T2 sink may be called before its matching verified producer and guard authorize it.
CANCELLED_BEFORE_DISPATCH is allowed only in the same live owner with a proven never-dispatched capability and disabled delivery source. A successor cannot infer it from ARMED. After dispatch, AbortController, timeout, rejected fetch, unsubscribe or an empty callback queue alone cannot resolve a child. Recovery needs the actual producer-specific proof or a demonstrated no-delivery barrier plus the required outcome reconciliation.
beginClose synchronously closes child admission and disables genuine action sources, then resolves all owned obligations. A queued genuine click, accessibility activation, pending parser, redirect/challenge or callback must be accounted for. Removing a node alone is not quiescence. Native disabled-button behavior and ownership handoff require actual browser tests; no fictional event-loop flush.
Sign-out intent arriving in the active owner immediately establishes17, even if every later write fails. It cannot be recast as an unpressed confirmation. A not-yet-dispatched disabled button is different from an already delivered intent. Account switch retires old scope and prevents old account painting without inventing authenticated account closure.
Before bulk sealing, capture the complete proof set and close basis. A new child/evidence/negative or owner/session change invalidates that candidate; newly required immutable bytes require restaging and resealing. A digest/frame flag cannot stand in for absent full evidence. Existing final frame fields may carry the permitted later sample only under the separately closed T1/local-sample contract.
finalize is synchronous at the existing serialized, same-IDB-transaction validation cut. Recheck full durable basis and live owner/session/observation state; no external await inside this final cut. This is an engineering constraint, not a theorem that every Promise continuation is inactive. A known negative arriving before commit processing begins must abort the affected operation batch; deliberate task-delayed delivery is a required witness.
After commit processing begins, success remains conditional on persistence. On successful complete preserve the actual disk facts, but a changed context receives no stale Saved/paint; on abort there is no operation/outbox/sequence/U advance. A new late negative stays known and starts/continues its own obligation; crossing the cut never licenses ignoring it.
Control-only refusal retains the exact prior body and U/sequence. It may preserve OPEN and known refusal but cannot invent a new proof, clear OPEN or install staged operations. Closure requiring new immutable proof bytes uses a newly sealed proof-bearing candidate, never the control-only shortcut. Clearing OPEN/checkpoint transitions require the reviewed semantic amendment; this file does not enable them.
releaseOwner requires no newly enabled producer and validated durable closure or explicit transfer of complete unresolved obligations to a successor that remains recovery-blocked. Transfer does not retire the old callbacks: their children stay unresolved until the actual delivery barrier is proved, and any late learned negative still belongs to that obligation. No release merely because the local command queue is empty. Lock loss/termination has no assumed finally/cleanup execution.
