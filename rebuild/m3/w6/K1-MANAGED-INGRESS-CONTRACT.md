## 1. Scope, ownership and earliest observation

Current acceptResponse receives a caller-owned response before guard.run (public-client118–128,154–157); execute/reopen reach permissionNowIso at82–85 without that guard. exchangeServerTime surrounds request creation at163–177. A guard around the trusted sink alone cannot protect earlier status/header/parser/UI/clock knowledge.
**Proposed owner profile:** one same-origin Web Lock semantic owner per authenticated installation namespace. It alone holds the private durable-client instance, verifier, permission evaluator, token/response parser and transport callbacks. Lock naming uses the exact namespace through a reviewed collision-free encoding; that encoding and supported-browser behavior remain binding-review items.
Other enrolled contexts forward bound intents through owned MessagePorts; they cannot directly invoke these private dependencies. Each intent carries immutable scope/session references, a fresh intentId and its captured input. Responses bind the same intent/scope; stale delivery cannot paint or clear another account's draft. This is a proposed coordination profile, not an accepted restriction of tab/PWA support.
No wall-time lease, heartbeat silence or timeout steals a lock. A paused owner is not a dead owner. After actual lock acquisition, a successor authenticates the stored pair and resolves inherited obligations before exposing truth. Lack of an owner/answer preserves the draft and supplies no success; its exact waiting UI must satisfy the existing concurrency contract before adoption.
The owner keeps network waits outside the short local stage/commit queue. A pending nonnegative network child does not itself forbid a separately permitted local write. Such a write preserves that child's OPEN root. Avoiding a permanent OPEN-per-session guard, mandatory lifetime network connection and automatic bounded-restart refusal is a REQUIRED BUT UNPROVED property: pre-arming continuously available UI controls can violate it, as the crash comparison below explains.
**Proposed auth profile:** no Clerk JS import in the enrolled offline context; use explicitly owned native-fetch requests for the ruled email-code flow and token/session actions. This excludes that SDK's timers/channels by composition, not by polling:false/touchSession:false/off. Actual FAPI request/cookie/challenge and W5 JWT bindings remain OPEN; this document does not implement them or assume a quiet SDK mode.

Online/offline/focus/visibility, storage events, worker messages and cookie changes may trigger owned intents; they are not authenticated revocation by themselves. Include every actual handler/import in the final producer manifest; unknown informative ingress prevents profile acceptance.
The first informative cut includes status/headers, body/error parsing, verification, cached/queued delivery and deliberate UI intent, not only application subscribers. Before any such cut the matching root/child must already be durable. Full raw data may be held opaque, but withholding a comparator does not erase knowledge already delivered to application code.

## 2. Proposed closed proof shapes

All new K1 wrapper/descriptor/capture shapes below are proposed version1 validators, not currently accepted production validators. Their unknown/missing fields, duplicate decoded keys, unexpected types, nonfinite/unsafe numbers and unsupported versions refuse18 before truth. These new field allowlists do NOT replace inherited W5/T3 signed-record validators: retain every original signed field and use the pinned existing contract, including its permitted extras. No object coercion. Full proof bytes remain encrypted in the existing frame body; its existing kind/version/digest/bytes envelope and strict parser remain unchanged.
Serialization proposal: UTF-8 JSON.stringify of closed objects constructed in the field order shown, no whitespace/newline, strings restricted to Unicode scalar sequences. IDs are32 lowercase hex characters from16 fresh random bytes, checked for collision in retained scope; they are identities, not cryptographic security budgets. References are lowercase64-hex digests or explicit null where allowed. Revision fields are positive safe integers. Arrays are dense; child IDs are unique and sorted by ASCII ID; duplicate memberships refuse.
Root proof: kind=guard, version=1; exact fields {protocol,rootId,namespace,athleteId,deviceId,ownerRef,sessionRef,basisRevision,predecessorGuardRef,phase,children,closureRef}. protocol is earned/k1/root/v1; namespace/athlete/device obey their existing authenticated contracts; ownerRef/sessionRef are nonnull immutable proof references; predecessorGuardRef is null only for verified initial absence. phase is OPEN, CLOSING or RESOLVED. closureRef is null unless phase=RESOLVED. children is the complete array of child records below, never only recently active children.
Child record: exact fields {childId,producer,phase,binding,rawRef,outcomeRef}. producer is one enum in §1. phase is ARMED, DISPATCHED, CAPTURED, RESOLVED or CANCELLED_BEFORE_DISPATCH. rawRef/outcomeRef are null until their full matching proofs exist. A durable ARMED record does not prove dispatch never happened after it; after restart it remains ambiguous until recovered.
Binding: exact fields {profile,requestId,method,route,requestDigest,opId,challengeRef,intentId,basisRef,ruleVersion}. profile/ruleVersion name exact reviewed source/schema versions; method is POST or LOCAL. route is the exact registered producer route/action. requestId/intentId are scoped IDs; requestDigest commits the exact request descriptor/body bytes below. Raw proof: kind=recovery, version=1; exact fields {protocol,rootId,childId,scopeRef,producer,requestId,profile,capture}. protocol is earned/k1/raw/v1; capture is the closed producer union. §§2.1–2.2 author the named W5 and LOCAL capture shapes. **AUTH_EXCHANGE/CONTEXT_SWITCH capture schemas, other local sources and sensitive auth custody remain OPEN; arbitrary JSON or silent redaction is not valid evidence.** No bearer token is copied into a proof merely because it arrived in a response.
Outcome proof: kind=recovery, version=1; exact fields {protocol,rootId,childId,rawRef,basisRef,ruleVersion,classifications,effectsRef}. protocol is earned/k1/outcome/v1. classifications is a nonempty duplicate-free array in this fixed order: STANDING_LOST, AUTH_REJECTION, ALLOWANCE_INVALIDATED, INTEGRITY_UNPROVEN, AUTH_EXPIRED_ONLY, NO_NEW_NEGATIVE, UNAVAILABLE; incompatible combinations are rejected by the producer rule. NO_NEW_NEGATIVE cannot coexist with a negative or UNAVAILABLE. effectsRef retains the complete immutable disposition/effect evidence, not a guessed success boolean.
Positive permission depends on the exact current basis and selected rule. Negative knowledge cannot be discarded merely because its observed basis became stale; validate scope/authenticity and preserve every independently applicable negative dimension from every unresolved raw proof. A changed token or successful unrelated request cannot discharge it.
Closure proof: kind=recovery, version=1; exact fields {protocol,rootId,ownerRef,sessionRef,childrenDigest,outcomeRefs,barrierProfile,barrierEvidenceRef,resolution}. protocol is earned/k1/closure/v1; childrenDigest commits the exact complete child array; outcomeRefs list every required resolution in child order. resolution is CLEAN or RETAINED_NEGATIVE. The exact barrier profile must prove stopped creation, retired delivery and each child's resolution; no caller assertion alone satisfies it.
Each changed root/proof is a new immutable entry; the frame selects its digest. Frame guard=OPEN for OPEN/CLOSING, resolved only for a validated RESOLVED root. H/W_last/U, invalidation, observationCounter and selected references remain authoritative only in the frame. Never spread historical retainedMetadata into permission or duplicate current counters into a root as alternative authority.
Root/proof growth cannot silently trim unresolved children, old signed operations, rejection knowledge or recovery evidence. Retention/size bounds and reclamation need an explicit reviewed rule tied to complete closure and P1/R1 requirements; unavailable space refuses with retained obligations.

### 2.1 W5 v1 bindings and captures — proposed manager contract

This table binds only the published W5 v1 routes; it does not amend their HTTP bodies, signatures, operation HMAC, canonicalization or lease semantics. Request descriptor has exact fields {serviceOrigin,origin,method,route,contentType,bodyB64}, in that order. serviceOrigin is the configured HTTPS service origin; origin is the permitted frontend origin; method=POST, contentType=application/json, and route is an exact table literal with no query/fragment. bodyB64 is canonical unpadded base64url of the exact UTF-8 JSON body bytes. requestDigest=SHA-256 of this descriptor's §2 serialization; it commits both endpoint/context and untouched body bytes. The owner captures this descriptor before durable arm and dispatches those same bytes. Authorization/Cookie values are not descriptor fields or evidence. Invalid configuration cannot be repaired by trusting response-declared origin.
Construct the listed body keys in order and serialize once; operation is the full original immutable T3 envelope, not a reconstruction from its canonical commitment. An operation retry retains that exact envelope and request bytes; its separately recorded attempt has a fresh local requestId. JSON transport must preserve the existing parsed operation/canonical bytes; it cannot silently coerce unsupported values. Worker request limit remains262144 bytes, not a newly selected history/capture limit.

## 3. Proposed API and transition requirements

The manager privately exposes beginObservation(binding), dispatch(handle,producer), capture(handle,raw), resolve(handle), beginClose(rootId), finalize(context) and releaseOwner(). Handles are scoped, candidate-bound capabilities; the same request may retry only under its original immutable identity and a separately recorded attempt. No public alreadyArmed flag or unowned callback can bypass dispatch.
beginObservation first authenticates the pair/current scope and builds the full root/child proof. Commit OPEN with full-pair CAS and await transaction complete before enabling the producer. Arm failure triggers zero controlled requests/samples/intent controls; retain input and return3 unless an independent stronger fault is already known. No knowledge-survival claim is made before that commit.
Adding a child requires its durable membership before dispatch; concurrent membership changes require restaging from the new complete basis. ARMED and DISPATCHED phases describe durable evidence, not proof of a maximum runtime phase. Children never allocate operations or allowance slots merely by existing.
capture preserves full relevant evidence before positive semantic use, while immediately latching independently learned17/19/20 and invalidating affected candidates. Capture/outcome-write failure leaves the already durable OPEN obligation. A failed raw write is not permission to declare the event unobserved or fall back to a positive old view.
resolve evaluates the exact retained raw/basis/rule version and persists complete consequences atomically. Authenticated rejection must commit rejected ledger, disposition and outbox change together and idempotently; accepted facts cannot be removed because a reply was lost. No ordinary trusted T2 sink may be called before its matching verified producer and guard authorize it.
CANCELLED_BEFORE_DISPATCH is allowed only in the same live owner with a proven never-dispatched capability and disabled delivery source. A successor cannot infer it from ARMED. After dispatch, AbortController, timeout, rejected fetch, unsubscribe or an empty callback queue alone cannot resolve a child. Recovery needs the actual producer-specific proof or a demonstrated no-delivery barrier plus the required outcome reconciliation.
beginClose synchronously closes child admission and disables genuine action sources, then resolves all owned obligations. A queued genuine click, accessibility activation, pending parser, redirect/challenge or callback must be accounted for. Removing a node alone is not quiescence. Native disabled-button behavior and ownership handoff require actual browser tests; no fictional event-loop flush.
Sign-out intent arriving in the active owner immediately establishes17, even if every later write fails. It cannot be recast as an unpressed confirmation. A not-yet-dispatched disabled button is different from an already delivered intent. Account switch retires old scope and prevents old account painting without inventing authenticated account closure.
Before bulk sealing, capture the complete proof set and close basis. A new child/evidence/negative or owner/session change invalidates that candidate; newly required immutable bytes require restaging and resealing. A digest/frame flag cannot stand in for absent full evidence. Existing final frame fields may carry the permitted later sample only under the separately closed T1/local-sample contract.
finalize is synchronous at the existing serialized, same-IDB-transaction validation cut. Recheck full durable basis and live owner/session/observation state; no external await inside this final cut. This is an engineering constraint, not a theorem that every Promise continuation is inactive. A known negative arriving before commit processing begins must abort the affected operation batch; deliberate task-delayed delivery is a required witness.
After commit processing begins, success remains conditional on persistence. On successful complete preserve the actual disk facts, but a changed context receives no stale Saved/paint; on abort there is no operation/outbox/sequence/U advance. A new late negative stays known and starts/continues its own obligation; crossing the cut never licenses ignoring it.
Control-only refusal retains the exact prior body and U/sequence. It may preserve OPEN and known refusal but cannot invent a new proof, clear OPEN or install staged operations. Closure requiring new immutable proof bytes uses a newly sealed proof-bearing candidate, never the control-only shortcut. Clearing OPEN/checkpoint transitions require the reviewed semantic amendment; this file does not enable them.
releaseOwner requires no newly enabled producer and validated durable closure or explicit transfer of complete unresolved obligations to a successor that remains recovery-blocked. Transfer does not retire the old callbacks: their children stay unresolved until the actual delivery barrier is proved, and any late learned negative still belongs to that obligation. No release merely because the local command queue is empty. Lock loss/termination has no assumed finally/cleanup execution.
