## 1. Workout behavior and closed command contract

The slice is done only when the owner can open the correct accepted prescription, start its workout, record what actually happened, recover an interruption, finish and inspect truthful history, and handle every offered decision or blocking state without returning to the frozen app. Each action retains typed values on refusal and states the applicable recovery action. No placeholder toast may claim a write.
Preserve the existing operation identity, athlete/device binding, sequence, predecessor/causal parents, effective date/time/offset, schema version, lease, canonical commitment and signed disposition contracts (R150–164). Request-supplied athlete IDs never establish scope. Replays preserve the full original operation under the accepted R1 typed-value/alias/recovery contract, as well as canonical commitment bytes; canonical equality alone is insufficient. Preserve R1's ENVELOPE_MISMATCH recovery path. Display edits never change accepted facts in place.

| Command / field contract | Required mapping and invariants |
|---|---|
| Start prescribed or ad-hoc workout | Envelope carries planned split slot or explicit AD_HOC discriminator and `plan_basis`; `session-start` payload is `{}` (R159,213,232). Allocate one stable start operation identity. Merely starting/logging never accepts a plan or proposal. Preserve the governing basis through interruption and cross-device reconciliation. |
| Log a set | `session-set` envelope carries `session_start_op_id`, `logical_set_slot`, `lift_lineage_id`; payload carries actual load with its immutable unit and reps (R159–164,213,233). Preserve each entered load independently, including mixed-load sets. A fixed pounds schema is permitted; no kilogram-entry feature is added here. Reject unsupported units rather than acknowledging a different unit. Never snap, average or substitute the prescribed scalar to fit an old writer. Slot allocation must remain stable on retry; concurrent attempts remain distinct until a recorded resolution. |
| Reserve / effort follow-up | Preserve the mock's exact meanings: 0, 1, 2, 3+, Not sure; asked first/last only; skipping assumes nothing (H409–421,468–476). Zero is an answer, unknown is not zero, and 3+ is a lower bound, not an exact three. A later answer to an already Saved set is a targeted append-only correction; do not delay or silently rewrite the acknowledged set. |
| Skip set or lift | Envelope identifies start, lineage, `skip_scope: lift | set`, and slot for set scope; optional reason in payload (R160–161,213,233–234). Skipped and not logged are not zero-rep observations. Correcting a skip preserves the original operation and its disposition. |
| Finish normally or early | `session-close` envelope names the start, never a set slot; payload includes `completion_kind` (R160,214,234–235). Early finish preserves every logged fact and leaves the rest not logged. No synthetic completed set, implicit progression acceptance or blind all-lifts-complete summary. Identical operation retry has one effect; distinct concurrent close operations remain recorded facts governed by the ratified resolution contract, never deduplicated solely by start ID. |
| Correct / remove / undo | A fact correction names its target and complete validated replacement fields; removal appends a reasoned tombstone (R96–110,206–210). | Choose an offer | Bind the authenticated issued instance, chosen outcome and exact consent digest to its displayed basis. No direct training-plan write from a presentation button. |
| Resolve workout/set ambiguity | Record the complete session partition, component generation, keyed answer commitment and chosen governing basis; record targeted set IDs, duplicate/distinct partition, canonical choices and replacement slots for set collisions (R162–163,214–216,235–236). Incomplete/stale answers cannot silently choose a workout or earn an advance. |
| Pain / illness / return | Reachable session-only or open-interval pain attestation, targeted interval close/correction, illness interval and applicable Re-entry choice (R203–205; B1/B4/B14). Withdraw affected machine advice immediately under existing safety/dependency rules; preserve unaffected acknowledged facts. No diagnosis, guessed recovery date or invented training adjustment. |
| Read / resume / history | Project authenticated accepted operations through contiguous W plus separately identified permitted local pending facts, with corrections/tombstones/rejections and workout partitions applied. Preserve original IDs, units, actual per-set values and governing plan provenance. History is real workout history across enrolled devices, not the current `face().history` suspension list or a date-only grouping. |

Stage A must publish the exact envelope schema before product implementation. The following are narrow **proposed technical encodings**, not claimed existing rulings: reserve is a tagged value `exact` with value 0/1/2 and unit rep; `at_least` with value 3 and unit rep; or `unknown`, `skipped`, `not_asked` without a numeric value. Here `skipped` means the effort question was skipped, not a set/lift skip; `not_asked` requires actual prompt context, never inference from missing legacy data. Completion kinds are `normal` and `early`. An optional field absent in old accepted operations stays absent; never rewrite old signed bytes to add these tags. Canonical absent/null/value remain distinct.
C reviews those technical spellings, unknown/absence preservation and legacy mappings before they are normative; C does not decide a new early-close training eligibility rule. If the existing training contract cannot determine a result, preserve the fact and existing uncertainty/suppression behavior; put the precise unresolved product question and red witness before the owner, rather than inventing a rule.
The schema publication also closes planned/ad-hoc discriminator representation, slot allocation, all required/forbidden fields, quantity units, correction compatibility, action-to-envelope placement, plan undo prerequisites, conflict/offer commitments and error codes. Test wrong/missing fields and legacy-version behavior at both client and authority boundaries.
