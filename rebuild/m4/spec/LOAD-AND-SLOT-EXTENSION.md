This is an explicit addition to the16 existing A3 kinds, requiring affected technical acceptance and a version-specific builder/admission amendment; it cannot be smuggled through legacy lineage/fact/Set or enabled by changing the global v1 kind list. Original version1 validation stays exact.

Its slots contain fixed within-extension indices, not a guessed future operation ID. The explicit three-member domain prevents collision with original `[lift_lineage_id,position]` slot tuples. This derived ID is never a regenerated current-count position on reload/retry. Each added slot names its actual lift lineage. The extension's row and every later Set/Skip must declare actual reference/ownership coverage. Existing captured slots remain in place; additions form a separate explicit sequence after their lift's captured slots, ordered from the complete accepted causal/athlete-log sequence. Concurrent additions remain distinct, never deduplicated by position or label. ## Exact index capture and fixed Skip coverage proposal

The actual W6 `client/index.cjs:commitBatch` calls workoutCommands.prepare before its single Ops.build assigns op_id from the device/sequence. It does not pass an operation ID to prepare. Current W6 continuation.mjs and M4 engine-history.cjs expand a lift-scope Skip across every known slot for that lift. That behavior becomes ambiguous once later slots can exist. Propose version2 lift-scope Skip with a required nonempty, unique ordered `slot_coverage` list recording exactly the slots the athlete selected to skip at that moment. Each entry is `{logical_set_slot}` for an original slot, or `{logical_set_slot,slot_definition_op_id}` for an added slot. Every member must resolve to the same actual Start/lift and its declared immutable definition; every definition joins the exact reference/ownership dependency union. It is a closed captured set of targets, not a future wildcard. The normal UI supplies the applicable remaining slots shown to the athlete; it does not include performed work or fabricate covered slots. A later extension, including a concurrent extension unseen by that device, stays unlogged rather than inheriting the old Skip.

Set-scope Skip retains one logical_set_slot and optional added-slot definition reference. Lift scope forbids that scalar identity and instead requires slot_coverage. Changing Skip scope requires one coherent resulting variant; a correction must replace/clear the relevant mutually exclusive fields together. This is an additional amendment beyond the cd543b7 model currently under review; that model and its review packet remain unchanged. Its acceptance would not implicitly accept this new field or extension semantics.

Proposed extension edits may change effective time only; original capture, indices, reference Start, source/basis and derived identities remain immutable. Removing the extension disables the added-slot request, never deletes or silently removes observed Set/Skip rows referring to it. An empty removed request may leave the active to-do list; any recorded child remains accessible with its immutable definition and removal context. Do not infer progression/completion eligibility or resurrect a decision when a definition is restored. The shared normalizer must reconcile this behavior with the reviewed noncascading edit semantics, causal/concurrent ordering, session partition/resolution and currentness. This section does not implement those reducers, decide eligibility or forbid preserving a late remote fact merely because the definition was removed locally.
