# Workout edits and original history — proposed schema2 closure v0.2

PRE-EDIT EXECUTABLE PROPOSAL. This closes concrete candidate choices for WORKOUT-SCHEMA-V2 C1/C2, subject to the existing affected technical review. It is not an installed reducer, issuer permission, a qualified legacy bridge or a change to an already-issued schema. The accepted runtime sheet A1/A4 requires append-only corrections/removals and correctable effective time; state15 declares causal order with athlete_log_seq as the concurrent tie-break. The D14 occurrence clause at lines2514–2516 explicitly accounts for targeting operations that themselves have been superseded. None of those clauses specifies every field-clearing or nested-edit consequence; the choices below are proposals, not attributed ratifications.

## Proposed exact choices

1. A correction still carries `payload:{replacement_fields:{...}}`, with at least one field. Existing quantity/effort replacements remain byte-for-byte the same shape. For an OPTIONAL field only, the exact map `{clear:true}` is a correction instruction to remove the field from the derived view. It is never a recorded observation, never null/unknown/zero, and never permitted in a newly recorded set's reserve. Empty maps, false/extra clear keys and clearing required fields are invalid. An absent replacement key leaves the current field untouched. Null remains a distinct value and is valid only in a field whose complete schema expressly allows null.
2. Original signed operations, their effective time, original capture and source bytes never change. The corrected effective time is a separate complete `{local_date,local_time,utc_offset}` replacement in replacement_fields; no partial date/offset default, host timezone conversion or current-clock substitution. Logical identities never derive from corrected dates. A changed Start date/slot becomes input to the existing candidate relation and invalidates the relevant generation even if a later edit restores an earlier visible value; this model does not allocate that generation or revive answers.
3. Editable Start fields are effective time and planned split slot classification; original plan_basis and prescription_capture remain immutable evidence of what was displayed. Editable Set fields are effective, load, reps and reserve. Editable Skip fields are effective, reason, skip_scope and logical_set_slot as one resulting valid scope/slot variant. Editable Close fields are effective and completion_kind. Start references, lift lineage and set identity/slot are not editable aliases; workout/duplicate/slot reassignment uses the explicit resolution contract. A mistaken capture cannot be rewritten into a different original prescription.
4. Correction targets can be the original Start/Set/Skip/Close or an existing correction/tombstone descended from one of them. Revising a correction replaces its entire nonempty `replacement_fields` map, which is validated against that correction's ORIGINAL target variant. Revising a tombstone may change its nonempty reason. No target ID, identity, class, kind, lease or signature may be changed by an edit. The UI's normal “correct this set now” targets the original set. Revising a past edit is a separately labelled history action.
5. A tombstone disables only the targeted operation's contribution. It does not delete a row or cascade through a Start's children. A removed Start leaves its Set/Skip/Close records accessible but their live session context requires the full normalizer. A tombstone of a correction removes that correction's effect; a tombstone of a tombstone removes that one removal. Two live removals still remove their target if only one is disabled. A new correction of a removed fact does not resurrect it; explicitly disabling every live removal does. These consequences must be reviewable before the corresponding Undo/removal UI is enabled.
6. Interpret a COMPLETE authenticated accepted prefix, not incoming array/arrival order. Every target and causal parent precedes the referring operation in athlete_log_seq, as required by actual admission. Process target dependencies from newest to oldest to determine which original operations and edits are live and to compute revised edit contents. Apply the live corrections to each target in causal order, using athlete_log_seq only for concurrent ties. Named-field patches preserve unnamed fields. A revised earlier edit retains its original logical position: with c1(load10), then c2(load20), then c3 revising c1 to30, the current load remains20; c3 is separately retained as later change provenance. A user intending current load30 instead corrects the original set.
7. Removing a later correction may expose an earlier value, but NEVER revives a retired decision/generation/permission. A field view is only input to full history and generation reduction. Track all original effect identities, active effects and their source positions, including nested changes. Projection does not mutate a plan or grant safety, completion eligibility, currentness or consent.
8. Unaccepted local work has no authoritative tie-break number. Preserve it separately and do not insert it into the accepted prefix. The eventual local overlay may show a fully causal pending chain, but concurrent pending edits must remain explicitly unresolved until the accepted order is known or the athlete records a supported resolution. A pending sequence is not athlete_log_seq.

This monotone provenance is NOT a complete generation preimage, currentness proof or answer-reuse permission. Pending types are checked before any accepted parsing. ## Version1 and unresolved legacy context

Version1 decoding reads the ACTUAL historical writer placements: Start payload.slot; Set payload.load/reps/lift/slot/session_start_id; Close payload.session_start_id. Preserve raw types and every original field. A label called lift is not a stable lift_lineage_id; a payload slot is not silently a canonical new-schema logical slot. Missing plan basis, capture, reserve, completion kind or start link remains unknown, never NO_ACCEPTED_PLAN, zero effort or normal completion. Existing v1 class-reading corrections targeting session facts remain visible. Original unusual numeric observations remain recorded evidence, not endorsed training-domain inputs.

The executable candidate below concentrates on edit meaning and preserves legacy identity context separately. A cross-version edit of a legacy source is marked LEGACY_BRIDGE_REQUIRED until the complete authenticated source/lineage/basis correspondence is established. This is not a final blanket prohibition on resuming imported history. The eventual bridge must support the owner's real records; it cannot fabricate their missing past instructions. The full closed version1 normalization/legacy write bridge, added slots, nonnumeric loads, context semantics and decision generation remain in the SAME schema2 closure.

The model applies only the already described legacy load/reps corrections and reasoned original-set removals to version1. A legacy envelope containing the new clear instruction, a revised edit, or another unsupported replacement remains LEGACY_EDIT_INTERPRETATION_REQUIRED with no current/liveness verdict for that root; original bytes remain accessible. An old-schema edit of a new-schema root likewise requires MIXED_SCHEMA_EDIT_BRIDGE_REQUIRED. A permissive historical validator is not authority to assign a newly invented meaning to its old bytes. The new edit semantics below operate only within the explicitly proposed version2 model until the full bridge is qualified.
